# 方向 A 设计草图：法条引用准确性评测基准（law-citation-bench）

> 状态：**M0 已实现（见 `benchmarks/law_citation_bench/`）**。本文是方案草图，M0 已落地可运行原型，M1–M3 待续。
> 目标：在 `verified-chinese-law-kb`（2327 条逐字核验条文）之上，构建一个**离线可跑、纯标准库、可量化模型法条能力**的评测基准。

---

## 1. 定位与价值主张

- **痛点**：主流法律 AI 在"引用具体法条"时高频幻觉——错引条文号、编造条文内容、张冠李戴。
- **真值来源**：本仓库 `verified-chinese-law-kb` 是**逐字核验、带版本轴**的法条真值集，天然适合做评测的 ground truth。
- **作品集信号**：直接对应"能定义并量化 AI 质量（评测/跑分）"——比纯终端工具更对口 **AI 法律 PM / 法律合规岗**。

## 2. 评测范式（3 个任务）

### T1 · 引用接地 Citation Grounding
- **输入**：一个法律问询，或一段"根据《X法》第 N 条……"的论述片段。
- **期望输出**：`{ law_code, article_number, 关键句 }`。
- **真值**：KB 中对应条文。
- **评分**：`article_number` 精确匹配（硬分，权重高）＋ 文本相似度（字符级 F1，软分）。

### T2 · 条文检索 Retrieval（RAG 能力）
- **输入**：自然语言法律问题。
- **期望输出**：Top-5 条文 ID。
- **真值**：由"查询—条文"映射给出的相关条文集。
- **评分**：Recall@5、MRR。基线检索用仓库内置稀疏检索（BM25-like，纯 stdlib），模型输出与之对照。

### T3 · 幻觉识别 Hallucination Detection
- **输入**：一段"引用了某条文"的文本（部分被受控扰动：替换数字 / 删句 / 张冠李戴到相近法条）。
- **期望输出**：三分类——`命中 / 未命中 / 篡改`。
- **真值**：与 KB 逐字比对结果。
- **评分**：Accuracy、Macro-F1。

## 3. 数据集构建（自动生成 · 离线 · stdlib）

- 以 KB 每条文为锚，用**模板法**生成 query（不依赖 LLM 改写，保证离线）：
  - 抽取条文中关键实体/动词短语作 query；
  - 正样本 = 该条文；负样本 = 同法其他条文 ＋ 跨法干扰条文。
- **幻觉样本**：对真值条文做受控扰动生成"篡改引用"。
- **规模**：2327 条锚 → 约 2k–5k 题，按难度分层（易/中/难）。

## 4. 评分与跑分（单机可跑）

- 纯 stdlib 评分脚本 `score.py`：精确匹配 ＋ 字符级/分词重叠（内置极简中文分词，默认 fallback 到字符级，可选 jieba 但非必需）。
- 可选 **LLM-judge** 作为软分补充（可插拔适配器，默认关闭以保证离线）。
- 输出：每模型 `grounding_score` 综合分 ＋ 分任务分 ＋ 难度分层分 → `leaderboard.csv`。

## 5. 模型适配器（可插拔）

统一接口 `ModelAdapter.generate(prompt) -> text`：

- 内置 OpenAI / 兼容 API 适配器；
- 本地 vLLM / ollama 适配器（占位）；
- **哑基线**：随机基线 / "总是返回首条"基线——用于校准，证明基准能区分好坏模型。

> 评测时仅"调用模型"需联网（用户自备 key）；**真值比对、评分、报告全离线**。

## 7. 与现有仓库的关系

- 复用 `verified-chinese-law-kb` 作为真值，**不重复存储数据**。
- 建议作为**独立 repo** `law-citation-bench` 发布（评测集与 KB 解耦，便于被他人引用跑分），本仓库在其 README 中互引。

## 9. 风险 / 单点故障（SPOF）

- **中文分词**：默认用轻量字符级重叠，避免引入 jieba / lxml 等原生扩展（遵循 DD-007 教训：离线可跑、依赖 pin）。
- **真值一致性**：以 KB 的 `verification_status = verified` 为唯一真值，避免评测集自身带幻觉。
- **模型 API 漂移**：适配器层隔离，评分逻辑与具体模型解耦。

## 10. 与"方向 B（扩覆盖）"的关系

方向 A 是**质量放大器**（让现有 KB 产生"跑分"信号）；方向 B 是**广度扩展**。两者正交，可并行。建议先 A 后 B：A 直接服务作品集目标，B 是内容运营。
